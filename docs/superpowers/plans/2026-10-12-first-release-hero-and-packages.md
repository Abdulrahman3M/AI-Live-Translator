# First Release, Project Hero, and Download Packages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the first GitHub Release as v1.0.7 with a language-neutral homepage hero and five verified downloadable packages.

**Architecture:** Keep the existing ChatGPT builder and add a focused standard-library builder for the Codex, Claude Code, portable Agent Skill, and source ZIPs. Update version metadata, bilingual docs, and the tag-triggered GitHub Actions release flow together; leave translation runtime behavior unchanged.

**Tech Stack:** Python 3 standard library, JSON, Markdown, GitHub Actions, Git, image generation.

**Spec:** `docs/superpowers/specs/2026-10-12-first-release-hero-and-packages-design.md`

## Global Constraints

- Set release metadata and package filenames to `1.0.7` / `v1.0.7`.
- Use these release asset names exactly: `AI-Live-Translator-ChatGPT-Plugin-v1.0.7.zip`, `AI-Live-Translator-Codex-Plugin-v1.0.7.zip`, `AI-Live-Translator-Claude-Code-Plugin-v1.0.7.zip`, `AI-Live-Translator-Agent-Skill-v1.0.7.zip`, and `AI-Live-Translator-Source-v1.0.7.zip`; use `AI-Live-Translator-v1.0.7/` as the source archive root.
- Use the canonical name **AI Live Translator** and short description **Translate messages both ways**.
- Keep the hero text-free, wide, and based on two people, speech bubbles, opposing arrows, and abstract language marks in navy, teal, and cyan.
- Preserve existing translation behavior and the safety contract; do not add network calls, telemetry, transcript storage, microphone access, credentials, or autonomous messaging.
- Keep the dedicated ChatGPT package generated by `plugin/installation/build-chatgpt.py`.
- Build the Codex, Claude Code, portable Agent Skill, and source ZIPs under ignored `dist/`; use `git ls-files --cached --others --exclude-standard -z` so local pre-commit builds include current nonignored project files, and exclude Git metadata, generated archives, caches, temporary files, and local environment/editor state.
- Keep concise bilingual installation guidance under `docs/` and command-by-command instructions under `plugin/installation/`.
- Run both mandatory checks from `AGENTS.md`; after successful verification, remove generated ZIPs and caches, commit only intended source files on `main`, push to `origin/main`, then push tag `v1.0.7` and verify the GitHub Release.

## Review Focus

- The source package must contain tracked project files only and must not recursively include `.git`, `dist`, caches, temporary files, or local environment folders; assert representative included and excluded paths.
- The bilingual pages and release notes must describe the same five download routes, feature set, and host-specific limitations; assert key localized links and feature names.
- A workflow run on a branch or untagged manual dispatch must not create a GitHub Release; assert the tag guard and notes-file use in the workflow.
